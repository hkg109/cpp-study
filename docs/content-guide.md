# 콘텐츠 작성법

## 발표용 강의 구성

강의는 **선수 지식·학습 목표 → 작은 예제 → 실행 추적 → 함께 풀기 → 확인 질문** 순서로 작성합니다. 발표자는 코드를 실행하기 전에 결과를 예상하게 하고, 실행 후에는 입력이나 한 줄만 바꾸어 다시 확인합니다. 시간은 권장값이며 참가자의 이해에 따라 나눠 진행합니다.

- 첫 문단은 강의 목록의 설명에도 사용됩니다. 이번 강의가 해결할 문제를 짧게 적습니다.
- 본문에는 처음 배울 핵심을 두고, 복잡한 선언·증명·다른 문법은 ‘보충’으로 구분합니다.
- 용어를 처음 쓸 때는 한국어 뜻과 작은 예를 함께 설명합니다. 코드의 결과만 적지 말고 변수의 변화와 이유를 보여 줍니다.
- 전체 프로그램과 코드 조각을 구분합니다. 서로 다른 예제의 같은 클래스나 main을 한 파일에 합치지 않도록 안내합니다.
- 전체 예제는 C++17 기준으로 작성하고, 필요한 헤더와 입력 범위를 명시합니다. 빈 목록·입력 실패·자료형 범위·자원 정리도 확인합니다.
- 일부러 틀린 코드는 오류 예시임을 밝히고, 정의되지 않은 동작은 실행해 답을 맞히는 문제로 만들지 않습니다.

### 권장 학습 순서

| 기본 강의 | 이어서 볼 보충 강의 |
| --- | --- |
| 0주차: 출력·변수·연산 | Exercise 02: 입출력과 정수 연산 |
| 1주차: 선택과 반복 | Exercise 03: 최대공약수, 최대 부분합은 도전 문제 |
| 2주차: 함수·재귀·스코프 | Exercise 04: 거듭제곱과 최소 변환을 별도 시간에 진행 |
| 3주차: 참조·배열·vector | Exercise 05: 퀵 정렬과 힙 정렬을 별도 시간에 진행 |
| 4주차: 포인터·동적 메모리 | const 포인터·C 문자열은 보충 |
| 5주차: 클래스·객체 | 추상 클래스는 보충 |
| 6주차: 파일 분리·예외 처리 | static·friend·연산자 오버로딩은 보충 |
| 7주차: 함수·클래스 템플릿 | 함수 선택·고정 크기 스택·템플릿 재귀는 보충 |

4~6주차의 기말 대비 접근 표와 출력 추적 문제는 기본 설명 뒤의 ‘시험 대비 보충’에 둡니다. 첫 수업에서는 본문의 예제를 먼저 익히고, 복습 시간에 보충 문제를 주제별로 나눠 진행합니다.

Exercise의 02~05는 기존 자료의 번호입니다. 파일 경로는 유지하고 각 강의에서 선수 강의로 연결합니다. 화면의 주차순 이전·다음 버튼과 권장 학습 순서가 다를 수 있으므로 수업은 본문의 안내를 따라 진행합니다.

### 발표 중 확인 질문

기존 학습 문법을 사용하면 답을 접어 두고 참가자가 먼저 생각할 수 있습니다. 질문과 답 사이에는 다른 블록을 넣지 않습니다.

```md
> [!QUIZ]
> 이 반복이 끝난 뒤 sum은 얼마인가요?

> [!ANSWER]
> 각 회차에서 더한 값을 따라가면 6입니다.
```

### 설명 정확성을 확인할 참고 자료

- 가상 함수와 오버라이딩: [C++ 표준 초안 class.virtual](https://eel.is/c++draft/class.virtual).
- 배열 매개변수의 포인터 조정: [C++ 표준 초안 dcl.fct](https://eel.is/c++draft/dcl.fct).
- 배열 범위 안의 포인터 연산: [C++ 표준 초안 expr.add](https://eel.is/c++draft/expr.add).
- 예외 전파와 역순 소멸: [C++ 표준 초안 except.ctor](https://eel.is/c++draft/except.ctor).

## 강의노트

`content/weeks`에 각 주차의 첫 강의는 `week-00.md`, 추가 강의는 `week-00-02.md`, `week-00-03.md` 형식으로 추가합니다. 강의 제목은 같은 폴더의 `titles.json`에서 파일명과 같은 키로 관리합니다.

```json
{
  "week-00": "Hello World, 자료형, 연산자",
  "week-00-02": "조건문 기초",
  "week-01": "표현식과 흐름 제어"
}
```

Markdown 본문은 첫 줄부터 일반 제목과 문단으로 작성합니다. 모든 `#`, `##`, `###` 제목은 본문에 표시되며 목차에도 반영됩니다.

```md
# 컴파일러란 무엇인가요?

컴파일 과정에 대한 설명입니다.

## 빌드 과정

세부 내용을 작성합니다.
```

## 실습

`content/practice`에 같은 주차 이름의 `.md` 파일을 추가합니다. 파일 상단에는 다음 frontmatter가 필요합니다.

```md
---
title: 실습 제목
description: 실습 설명
week: 3
order: 1
published: true
---

## Q1. 문제 제목

문제 내용을 작성합니다.
```

정답 코드는 `<Answer>` 안에 넣으면 접힌 상태로 표시됩니다.

````md
<Answer label="예시 코드 보기">

```cpp
#include <iostream>
using namespace std;

int main() {
  cout << "Hello" << endl;
  return 0;
}
```

</Answer>
````

## 공통 규칙

- 첫 강의 파일명은 `week-주차.md`, 추가 강의는 `week-주차-강의번호.md` 형식으로 작성합니다.
- 같은 주차·강의 번호를 두 개 만들지 않습니다. `week-4.md`는 4주차 1번 강의이므로 `week-04-01.md`와 동시에 사용할 수 없습니다.
- C++ 코드는 언어 이름이 `cpp`인 코드 블록으로 작성하면 문법 강조와 복사 버튼이 붙습니다.
- 이미지는 `public/images`에 넣고 `![설명](/images/example.png)`처럼 연결합니다.
- 공개하지 않을 초안은 콘텐츠 폴더 밖에 보관합니다.
- 배포 사이트에는 GitHub push와 Vercel 재배포가 끝난 뒤 반영됩니다.

로컬에서는 `npm run dev` 실행 중 저장한 변경을 자동으로 감지합니다. 관리자 모드를 이용한 파일 직접 수정 기능도 로컬 개발 환경에서만 동작합니다.
