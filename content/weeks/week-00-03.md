## 핵심 개념

`static_cast<double>(total) / count`처럼 나눗셈 전에 자료형을 바꾸면 실수 나눗셈을 할 수 있습니다. 실수에서 정수로 변환하면 표현 가능한 범위 안에서는 소수 부분을 0 방향으로 버립니다. 중괄호 초기화는 축소 변환을 제한합니다. 부동소수점은 유한한 비트로 값을 근사하므로 0.1 같은 값도 정확히 저장하지 못할 수 있습니다.

`if / else if / else`는 조건을 순서대로 검사해 처음 참인 분기 하나를 실행합니다. `switch`는 정수·열거형 값에 따라 분기하며, `break`가 없으면 다음 case로 이어질 수 있습니다. `&&`는 모두 참, `||`는 하나 이상 참, `!`는 참·거짓 반전입니다.

`while`은 실행 전에 조건을 확인하므로 0번 실행될 수 있고, `do while`은 본문을 먼저 실행하므로 최소 1번 실행됩니다. `for`는 초기화 → 조건 → 본문 → 갱신 순서입니다. `break`는 반복을 끝내고 `continue`는 현재 회차의 나머지를 건너뜁니다. `for`의 continue 다음에는 갱신식이 실행됩니다. `++x`는 증가한 값, `x++`는 증가 전 값을 표현식의 결과로 사용합니다.

반복문에서는 **무엇을 저장하고 있는가**, **한 회차에서 무엇이 바뀌는가**, **언제 끝나는가**를 먼저 정합니다. 최대공약수에서는 두 수와 나머지를, 최대 부분합에서는 현재 위치에서 끝나는 최대 합과 전체 최대 합을 유지합니다.

## Exercise 03

### Quiz 1 - 최대공약수

> **난이도:** 중

#### 요구사항

- 두 양의 정수의 최대공약수를 구합니다.
- 두 수를 나누어떨어지게 하는 양의 정수 중 가장 큰 값을 출력합니다. 아래 풀이는 유클리드 호제법을 사용합니다.
- 결과 뒤에 줄바꿈을 출력합니다.

#### 입력

한 줄에 1 이상 1,000,000,000 이하의 두 정수 a, b가 주어집니다.

#### 출력

a와 b의 최대공약수를 출력합니다.

#### 입력 예시

~~~text
48 18
~~~

#### 출력 예시

~~~text
6
~~~

#### 원문 추가 예제

| 입력 | 출력 | 확인할 점 |
| --- | --- | --- |
| 17 13 | 1 | 서로소이면 최대공약수는 1 |
| 987654312 765432108 | 36 | 큰 정수에서도 같은 나머지 반복 사용 |

#### 접근 방법

- 모든 수를 1부터 차례로 검사하면 최대 10억 번의 검사가 필요하므로 너무 느립니다.
- 유클리드 호제법의 성질 gcd(a, b) = gcd(b, a % b)를 사용합니다.
- b가 0이 될 때 남아 있는 a가 최대공약수입니다.
- 반복할 때마다 두 번째 값이 나머지로 작아지므로 매우 빠르게 종료됩니다.

<Answer>

~~~cpp title="exercise03_quiz1.cpp" showLineNumbers
#include <iostream>
using namespace std;

int main() {
    // a와 b는 최대 1,000,000,000이고 나머지는 항상 b보다 작다.
    // 따라서 모든 계산이 int 범위 안에서 이루어진다.
    int a;
    int b;
    cin >> a >> b;

    // b가 0이 될 때까지 유클리드 호제법을 반복한다.
    while (b != 0) {
        // 다음 단계에서 사용할 나머지를 먼저 보관한다.
        const int remainder = a % b;

        // gcd(a, b)는 gcd(b, a % b)와 같다.
        a = b;
        b = remainder;
    }

    // 반복이 끝나면 a에 최대공약수가 남는다.
    cout << a << '\n';

    return 0;
}
~~~

</Answer>

#### 코드 해설: 나머지를 보관한 뒤 두 값을 이동

`a`, `b`는 매 반복에서 최대공약수를 구할 두 수입니다. `while (b != 0)`은 두 번째 수가 0이 아닐 때만 나머지를 계산합니다.

~~~text
remainder = a % b    이전 a와 b로 나머지 계산
a = b                두 번째 수를 첫 번째 자리로 이동
b = remainder        나머지를 두 번째 자리로 이동
~~~

이 순서가 중요합니다. 먼저 `a = b`를 실행하고 `b = a % b`라고 쓰면 원래 `a`가 사라져 `b % b = 0`을 계산하게 됩니다. 그래서 임시 변수 `remainder`가 필요합니다.

#### 수학 공식: 왜 gcd(a, b) = gcd(b, a % b)인가요?

`gcd`는 두 수의 최대공약수입니다. 나눗셈의 몫을 `q`, 나머지를 `r`이라고 하면 `a = q × b + r`이고, 이를 바꾸면 `r = a - q × b`입니다.

1. 어떤 수 `d`가 `a`와 `b`를 모두 나누면, `q × b`도 나눕니다. 따라서 둘의 차이인 `r = a - q × b`도 나눕니다.
2. 반대로 `d`가 `b`와 `r`을 모두 나누면, 두 항을 합친 `a = q × b + r`도 나눕니다.
3. 따라서 `(a, b)`의 공약수와 `(b, r)`의 공약수는 정확히 같습니다. 가장 큰 공약수도 같습니다.

문제의 정답은 보존하면서 두 번째 수를 더 작은 나머지로 바꾸는 것입니다. 마지막에는 `gcd(a, 0)`이 되는데, 양의 정수 `a`와 0의 최대공약수는 `a`입니다. 0은 `a × 0`으로 표현되므로 `a`로 나누어집니다.

#### 실제 입력 48 18 추적

| 반복 | 계산 전 `a` | 계산 전 `b` | `remainder = a % b` | 갱신 후 `(a, b)` |
| --- | --- | --- | --- | --- |
| 1 | 48 | 18 | 12 | `(18, 12)` |
| 2 | 18 | 12 | 6 | `(12, 6)` |
| 3 | 12 | 6 | 0 | `(6, 0)` |

다음 조건 검사에서 `b != 0`이 거짓이므로 종료하고 `a`, 즉 `6`을 출력합니다. `48 = 6 × 8`, `18 = 6 × 3`이므로 실제로 둘 다 나누어집니다.

입력이 반대로 `18 48`이어도 처음에 `18 % 48 = 18`이 되어 `(48, 18)`로 바뀝니다. 미리 두 수를 정렬할 필요가 없습니다. `7 7`처럼 같으면 한 번 만에 `(7, 0)`이 됩니다.

나머지는 항상 나누는 수보다 작습니다. 또한 양수인 두 번째 값은 늦어도 두 번의 나머지 연산마다 절반 미만으로 줄어들므로, 약수를 하나씩 검사하는 것보다 훨씬 적은 반복으로 끝납니다.

#### 복잡도

- 시간 복잡도: O(log(min(a, b)))
- 공간 복잡도: O(1)

### Quiz 2 - 연속 부분 배열의 최대 합

> **난이도:** 중상

#### 요구사항

- 하나 이상의 연속된 원소를 선택합니다.
- 선택한 연속 구간에서 만들 수 있는 가장 큰 합을 구합니다.
- 모든 값이 음수인 경우도 올바르게 처리합니다.

#### 입력

첫째 줄에 1 이상 100 이하의 n이 주어지고, 둘째 줄에 -100 이상 100 이하의 정수 n개가 주어집니다.

#### 출력

비어 있지 않은 연속 부분 배열의 최대 합을 출력합니다.

#### 입력 예시

~~~text
5
-2 3 -1 4 -5
~~~

#### 출력 예시

~~~text
6
~~~

#### 원문 추가 예제

| 첫 줄 n | 둘째 줄 | 출력 | 확인할 점 |
| --- | --- | --- | --- |
| 4 | -8 -3 -6 -2 | -2 | 빈 구간을 고르면 안 되므로 답이 0이 아님 |
| 1 | 0 | 0 | 원소 하나도 유효한 구간 |

#### 접근 방법

- 연속 구간의 시작과 끝을 모두 시도하면 O(n²) 방식으로도 n=100에서는 통과할 수 있습니다.
- 하지만 각 위치에서 끝나는 최적의 합만 유지하는 카데인 알고리즘을 사용하면 O(n)에 해결할 수 있습니다.
- currentSum은 현재 원소에서 새 구간을 시작하는 값과 이전 구간에 현재 원소를 붙인 값 중 큰 값입니다.
- 모든 값이 음수일 수 있으므로 합을 0으로 초기화하면 안 됩니다. 첫 번째 입력값으로 currentSum과 maximumSum을 초기화해야 합니다.

~~~text
currentSum = max(현재 값, currentSum + 현재 값)
maximumSum = max(maximumSum, currentSum)
~~~

<Answer>

~~~cpp title="exercise03_quiz2.cpp" showLineNumbers
#include <algorithm>
#include <iostream>
using namespace std;

int main() {
    // n은 최대 100이므로 반복 횟수와 배열 위치는 int가 적합하다.
    int n;
    cin >> n;

    // 각 값은 -100~100이고 가능한 합도 -10,000~10,000이므로
    // value와 누적 합 모두 int로 안전하게 표현할 수 있다.
    int value;
    cin >> value;

    // 첫 값으로 초기화해야 모든 입력이 음수인 경우도 올바르게 처리된다.
    int currentSum = value;
    int maximumSum = value;

    for (int i = 1; i < n; i++) {
        cin >> value;

        // 이전 구간을 이어 갈지, 현재 값부터 새로 시작할지 선택한다.
        currentSum = max(value, currentSum + value);

        // 지금까지 발견한 가장 큰 연속 구간 합을 갱신한다.
        maximumSum = max(maximumSum, currentSum);
    }

    cout << maximumSum << '\n';
    return 0;
}
~~~

</Answer>

#### 코드 해설: 두 합의 의미를 구분하기

| 변수 | 정확한 의미 |
| --- | --- |
| `value` | 방금 읽은 현재 숫자 |
| `currentSum` | **현재 숫자에서 반드시 끝나는** 연속 구간 중 최대 합 |
| `maximumSum` | 지금까지 읽은 범위 전체에서 발견한 최대 합 |

`currentSum`은 현재 위치에 따라 작아질 수 있지만, `maximumSum`은 이미 찾은 좋은 답을 보관하므로 작아지지 않습니다.

1. 첫 번째 숫자를 읽고 두 합을 모두 그 값으로 초기화합니다. 길이 1인 구간도 정답 후보입니다.
2. 두 번째 숫자부터 읽으면서 이전 구간을 이어 갈지, 현재 숫자부터 새로 시작할지 결정합니다.
3. 결정한 `currentSum`과 기존 `maximumSum`을 비교해 전체 정답을 갱신합니다.
4. 숫자를 모두 읽은 뒤 `maximumSum`을 출력합니다.

#### 점화식: 왜 두 경우만 비교하나요?

현재 숫자를 `x`라고 해 봅시다. 현재 위치에서 끝나는 비어 있지 않은 연속 구간은 두 종류뿐입니다.

- **새로 시작:** 현재 숫자 하나만 선택합니다. 합은 `x`입니다.
- **이전 구간 연결:** 바로 이전 위치에서 끝나는 구간 뒤에 `x`를 붙입니다. 그중 가장 좋은 합은 `이전 currentSum + x`입니다.

~~~text
새 currentSum = max(x, 이전 currentSum + x)
새 maximumSum = max(이전 maximumSum, 새 currentSum)
~~~

이전 위치에서 끝나는 구간들은 모두 같은 `x`를 더하므로, 그중 최대 합 하나만 기억하면 충분합니다. 이전 합이 음수라면 붙일수록 손해이므로 버리고, 양수라면 연결하는 편이 유리합니다.

> [!CAUTION]
> 음수 원소를 무조건 건너뛰면 안 됩니다. 구간은 **연속**이어야 합니다. 예시의 `3`과 `4`를 함께 선택하려면 사이의 `-1`도 반드시 포함해야 합니다.

#### 실제 입력 5 / -2 3 -1 4 -5 추적

첫 입력 `5`는 원소 개수입니다. 첫 원소 `-2`를 읽은 뒤 `currentSum = maximumSum = -2`로 시작합니다.

| 위치 | `value` | 새로 시작 | 이전 합에 연결 | 갱신한 `currentSum` | `maximumSum` | 현재 위치에서 끝나는 선택 구간 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | -2 | -2 | 초기화 | -2 | -2 | `[-2]` |
| 2 | 3 | 3 | `-2 + 3 = 1` | 3 | 3 | `[3]` |
| 3 | -1 | -1 | `3 - 1 = 2` | 2 | 3 | `[3, -1]` |
| 4 | 4 | 4 | `2 + 4 = 6` | 6 | 6 | `[3, -1, 4]` |
| 5 | -5 | -5 | `6 - 5 = 1` | 1 | 6 | `[3, -1, 4, -5]` |

마지막 `currentSum`은 1이지만 정답은 6입니다. 가장 좋은 구간이 마지막 원소에서 끝날 필요는 없기 때문에 `maximumSum`을 따로 저장합니다. 표의 구간은 이해를 위한 표시이며 실제 코드는 구간 자체를 저장하지 않습니다.

#### 모든 값이 음수인 경우

입력이 `3`과 `-8 -3 -6`이면 다음처럼 됩니다.

~~~text
첫 값 -8: currentSum = -8, maximumSum = -8
다음 -3: max(-3, -8 + -3) = -3 → maximumSum = -3
다음 -6: max(-6, -3 + -6) = -6 → maximumSum = -3
정답: -3
~~~

처음부터 `maximumSum = 0`으로 두면 실제로 선택할 수 없는 빈 구간의 합 0을 답으로 내놓게 됩니다. 문제는 하나 이상을 선택하라고 했으므로 첫 원소로 초기화해야 합니다. `n = 1`이면 반복문 없이 그 첫 원소가 답입니다.

`vector<int>`로 입력을 저장해도 시간은 O(n)이지만 저장 공간이 O(n) 필요합니다. 이 문제는 과거 원소를 다시 읽을 필요가 없어 입력을 하나씩 처리하는 현재 코드가 O(1) 추가 공간으로 충분합니다.

#### 복잡도

- 시간 복잡도: O(n)
- 공간 복잡도: O(1)
